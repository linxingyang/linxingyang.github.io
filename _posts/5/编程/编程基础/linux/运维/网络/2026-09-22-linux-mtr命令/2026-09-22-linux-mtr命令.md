# 说明

## 概念

MTR（全称 **My TraceRoute**，也作 **Matt's TraceRoute**）是一款网络诊断工具，把 `ping` 和 `traceroute` 的能力合二为一：
- 像 `traceroute` 一样**逐跳追踪**到达目标的完整路径；
- 像 `ping` 一样**持续发送探测包**，并对每一跳统计丢包率、延迟（最小/平均/最大/标准差）等指标。

传统 `traceroute` 每跳通常只探测一次，结果容易受节点瞬时抖动影响；`mtr` 会对路径上的每个节点持续探测并实时汇总统计，因此能更准确地定位「具体哪一跳」出现了延迟升高或丢包，尤其适合排查**间歇性、波动性**的网络故障。

## 典型使用场景

- 定位延迟/丢包发生在路径上的哪一跳；
- 排查跨境、跨运营商链路质量（配合 `-z` 看 AS 号）；
- 长时间持续监控链路稳定性（交互模式实时刷新）；
- 快速生成报告贴工单或写脚本（`-r` 报告模式）。

## 跨平台
- Linux 直接安装 `mtr` 软件包（Debian/Ubuntu 用 `apt install mtr`，RHEL/CentOS 用 `yum install mtr`）；
- macOS 用 `brew install mtr`；
- Windows 无原生 mtr，可用 **WinMTR** 替代。Windows 自带的 `pathping` 是同类工具（两阶段式路由 + 丢包统计），用途类似。

# 基础示例

```shell

**怎么读这份报告**：第 4、5、8 跳出现了 40%/20%/40% 的丢包，但从第 9 跳到目标（16 跳 `dns.google`）全程 0%，说明端到端链路其实是通的，中间那几跳的"丢包"是路由器对 ICMP 限速或不响应，并非真实故障。

### `???` 是什么意思？

该路由器收到了你的探测包，但它**没有返回 ICMP 超时回复**（或者回复在返回途中丢失了）。

**`???` 不代表丢包！** 只要 `???` 之后的节点仍然能正常返回信息（0% 丢包），说明网络是通的，中间那个路由器只是"不愿意回复"而已。

从你的数据看，第 6、7 跳是 `???`，但第 8 跳（`11.82.1.52`）、第 9 跳又能正常显示；第 10、11 跳是 `???`，第 12 跳（`172.16.10.38`）也正常显示 —— 说明这些只是路由器不回复，链路本身是通的。

### 1 到 16 的顺序是什么意思？

1 到 16 代表 ping 包从你的源主机到目标主机依次经过的每一跳路由器。

### 丢包率如何计算？

MTR 对**每一跳独立计算丢包率**，计算方式是：第 N 跳丢包率 =（发给第 N 跳的探测包未收到回复的数量）/（发给第 N 跳的探测包总数）× 100%

```
对于第4跳：
  MTR 发送 TTL=4 的包 → 经过前 3 跳路由器 → 到达第 4 跳路由器
  → 第 4 跳路由器应该返回 ICMP Time Exceeded
  → 5 个包里只收到 3 个回复 → 丢包率 = 40% ✅

对于第5跳：
  MTR 发送 TTL=5 的包 → 经过前 4 跳 → 到达第 5 跳路由器
  → 第 5 跳路由器应该返回 ICMP Time Exceeded
  → 5 个包里收到 4 个回复 → 丢包率 = 20% ✅
```

### 如何判断是 ICMP 限速还是真丢包？

- **中间节点丢包但后续节点不丢包**：通常是该路由器**限速 ICMP** 或不响应，不代表真正丢包
- **从某一跳开始持续丢包到目标**：说明该节点到下一跳之间的链路**确实存在问题**
- **重点看最后几跳的丢包率**：这才是反映端到端真实质量的指标

```
真实情况（ICMP限速）:
                    ICMP限速        ICMP限速        ICMP限速
  第1跳 ✅回复  →  第4跳 ⚠️丢回复 → 第5跳 ⚠️丢回复 → 第8跳 ⚠️丢回复 → 第9跳 ✅回复
     0%              40%             20%             40%             0%
     │
     └─ 说明这些路由器只是"懒得回复"，但数据包都正常转发了
```

```
真实链路丢包:
  第1跳 ✅  →  第2跳 ✅  →  第3跳 ❌开始丢  →  第4跳 ❌继续丢  →  第5跳 ❌继续丢
     0%          0%            30%               30%              30%
                 │
                 └─ 从某一跳开始丢包且持续到终点，这才是真实丢包
```

### 一、探测对象与方式：测谁、怎么发（hostname / -F / -4 / -6 / -u / -T / -P / -L / -a）

| 参数 | 说明 |
|---|---|
| `hostname` | 探测目标，域名或 IP |
| `-F FILE` | 从文件读取多个目标（批量探测） |
| `-4` / `-6` | 强制 IPv4 / IPv6 |
| （默认） | ICMP Echo 探测（同 ping） |
| `-u` | UDP 数据报（默认端口 33000，目标返回 Port Unreachable） |
| `-T` | TCP SYN（默认端口 80，目标返回 SYN-ACK/RST） |
| `-P PORT` | 配合 `-T`/`-u` 指定端口：`-T` 为目标端口；`-u` 为起始端口（逐包 +1） |
| `-L PORT` | UDP 源端口 |
| `-a ADDRESS` | 绑定本机源 IP（须是本机网卡真实地址） |
| `-I NAME` | 指定探测出口网卡（多网卡场景） |

```bash
# 目的端
mtr -r -c 5 8.8.8.8             # 直接指定目标
mtr -6 -r -c 5 2400:3200::1     # 仅走 IPv6

cat targets.txt                 # 批量：文件每行一个目标
# 8.8.8.8
# 1.1.1.1
mtr -r -c 5 -F targets.txt      # 依次输出每个目标的报告

# 探测协议
mtr -u -r -c 5 8.8.8.8            # UDP 探测（默认从 33000 起，逐包 +1）
mtr -T -r -c 5 8.8.8.8            # TCP SYN 探测（默认 80 端口）
mtr -T -P 443 -r -c 5 8.8.8.8     # TCP SYN 探测 443 端口（最常用）
mtr -u -P 50000 -r -c 5 8.8.8.8   # UDP 从 50000 端口开始探测
mtr -u -L 40000 -r -c 5 8.8.8.8   # 固定 UDP 源端口

# 源端
mtr -a 192.168.1.224 -r -c 5 8.8.8.8  # 指定从哪个本机 IP 出去
```

#### 为什么默认 ICMP 经常"不准"  - 为何使用TCP/UDP模式？

ICMP 属于控制面协议（非业务流量），防火墙/运营商/目标主机常对它限速或直接丢弃，于是出现 `???`、中间跳假丢包等假象——"ping 不通"不等于"业务不通"。换 TCP/UDP 相当于把探测包**伪装成正常业务流量**，更容易穿过这些限制，结果更贴近真实用户体验。

注意：中间跳始终靠路由器返回 ICMP Time Exceeded 来发现，换的只是**探测包本身**。

到达终点后，靠目标的响应确认"真的到了"（三种协议对比）：

| 协议 | 默认端口 | 到达确认方式 | 特点 |
|---|---|---|---|
| ICMP（默认） | 无 | Echo Reply | 最易被限速/丢弃，易假丢包 |
| UDP `-u` | 33000（起始，逐包 +1） | 目标回 Port Unreachable | 像普通 UDP 流量，穿透性好 |
| TCP `-T` | 80（固定） | 目标回 SYN-ACK（端口开）/ RST（端口关） | 测业务真实路径 |
- `-P PORT` 语义：对 `-T` 是目标端口；对 `-u` 是**起始端口**，之后每个探测包 +1。
- TCP SYN 只完成三次握手的前两步，收到响应后立刻发 RST，**不会真正建立连接**，对目标几乎无负载。
- 别和传统 `traceroute` 混淆：它的 UDP 默认起始端口是 33434，而 mtr 是 33000。

适用场景：
- 中间设备对 ICMP 限速/丢弃导致 `???` 或假丢包 → 换 UDP/TCP 结果更真实
- `-T -P 443` 测业务真实路径（排查"服务通但 ping 不通"）
- `-a` 用于多网卡机器指定出口、验证策略路由/分线路

`-u`/`-T` 底层依赖 raw socket：源码安装通常需 root；多数发行版包已用 setuid/cap_net_raw 给 `mtr-packet` 授权，普通用户可直接跑。`-L` 一般用于穿过按源端口做哈希的设备；绑定不存在的地址会报 bind 错误。


### 二、探测包与时序控制：发多大、发多快（-s / -B / -Q / -i / -G / -Z / -M）

| 参数 | 说明 |
|---|---|
| `-s SIZE` | 探测包大小（字节，含 IP 与 ICMP 头，默认 64） |
| `-B NUM` | payload 比特填充模式 |
| `-Q TOS` | IP 头 ToS 字段（QoS 等级） |
| `-i SECONDS` | 探测间隔（<1 秒需 root） |
| `-G SECONDS` | 最后一批探测后等待迟到响应的秒数（默认 5） |
| `-Z SECONDS` | 探测 socket 保持打开的秒数（默认 5） |
| `-M MARK` | 给包打 SO_MARK（配合策略路由，需 root） |

```bash
mtr -s 1472 -r -c 5 8.8.8.8   # 1472+20(IP)+8(ICMP)=1500 满包，测 MTU/分片
mtr -Q 46  -r -c 5 8.8.8.8    # ToS=EF，模拟高优先级语音流量
mtr -i 0.5 -r -c 20 8.8.8.8   # 加快探测节奏
mtr -G 3  -r -c 5 8.8.8.8     # 收尾等待缩到 3 秒，报告更快出
sudo mtr -M 0x100 -r -c 5 8.8.8.8  # 让探测包命中特定策略路由
```

输出均同标准报告。`-Q` 可验证运营商/云内网对不同 QoS 等级的路径差异；`-B` 用于测试设备对特定比特串的异常处理，极少使用。

| `-m TTL` | 最大跳数（默认 30） |
| `-U NUM` | 连续 N 跳无响应则提前停止（默认 5） |

mtr -f 3 -r -c 5 8.8.8.8   # 从第 3 跳开始显示

### 四、报告模式：怎么输出给人看（-r / -c / -w）

| 参数 | 说明 |
|---|---|
| `-r` | 报告模式（跑完退出，脚本/工单首选） |
| `-c COUNT` | 每跳探测包数量（默认 10） |
| `-w` | 宽格式（不截断主机名，配合 `-b` 才能完整显示 `主机名 (IP)`） |

```bash
mtr -r -c 10 -w -b 8.8.8.8
```

```
Start: 2026-09-28T10:00:00+0800
HOST: ecs-1706                                     Loss%   Snt   Last   Avg  Best  Wrst StDev
  1. gateway.local (192.168.1.1)                    0.0%    10    1.2   1.5   1.0   2.3   0.4
  ...
  4. dns.google (8.8.8.8)                           0.0%    10   15.2  15.0  14.5  16.0   0.5
```

不加 `-w` 时主机名/IP 会被截断，排查 CDN 节点（域名很长）务必加 `-w`；报告模式下 `-b` 显示的 IP 也要靠 `-w` 才能完整展示（手册：In report mode... they will be truncated. Use the wide report (-w) mode to see the IPs）。

### 五、结构化输出：给程序看（-j / -x / -C / -l / -p）

| 参数 | 格式 |
|---|---|
| `-j` | JSON |
| `-x` | XML |
| `-C` | CSV |
| `-l` | raw 原始逐条输出 |
| `-p` | split：某跳数据变化即输出该跳一行（增量格式） |

```bash
mtr -j -c 5 8.8.8.8    # 接入监控/告警
mtr -x -c 5 8.8.8.8    # 输出 XML
mtr -C -c 5 8.8.8.8    # 导入 Excel 分析
mtr -l -c 5 8.8.8.8    # 外部程序逐条消费
mtr -p 8.8.8.8         # 持续采集（配合 mtr-gtk 等前端）
```

```bash
mtr -j -c 5 8.8.8.8
```

```json
{
    "report": {
        "mtr": {
            "src": "ecs-1706",
            "dst": "8.8.8.8",
            "tos": 0,
            "tests": 5,
            "psize": "64",
            "bitpattern": "0x00"
        },
        "hubs": [

                "count": 1,

```

> 注意：`hubs` 里的统计值是**数字**（`Loss%` 也不带 `%` 号）；`mtr` 元信息里 `tos`/`tests` 是数字，`psize`/`bitpattern` 是字符串。

```bash
mtr -x -c 5 8.8.8.8
```

```xml
<MTR SRC="ecs-1706" DST="8.8.8.8" TOS="0x0" PSIZE="64" BITPATTERN="0x00" TESTS="5">
  <HUB COUNT="1" HOST="192.168.1.1">
    <Loss>0.0</Loss><Snt>5</Snt><Last>1.2</Last>
    <Avg>1.5</Avg><Best>1.0</Best><Wrst>2.3</Wrst><StDev>0.4</StDev>
  </HUB>
</MTR>
```

> 注意：属性是 `BITPATTERN`（全大写）；XML 标签不允许 `%`，所以丢包标签是 `<Loss>` 而非 `<LossPercent>`；标签名与报告列名一致（`Snt`/`Wrst` 等）。

```bash
mtr -C -c 5 8.8.8.8
```

```
Mtr_Version,Start_Time,Status,Host,Hop,Ip,Loss%,Snt,Last,Avg,Best,Wrst,StDev
MTR.0.95,1695874800,OK,8.8.8.8,1,192.168.1.1,0.00,5,1.20,1.50,1.00,2.30,0.40
```

> 注意：`Start_Time` 是 **Unix 时间戳**（秒），不是 ISO 时间；版本列格式为 `MTR.x.yz`；首行为表头；加 `-z` 还会多一列 `Asn`。

```bash
mtr -l -c 5 8.8.8.8
```

```

p 0 1200
h 1 10.0.0.1
p 1 5300
```

`h` 行为每跳主机信息（索引从 0 开始），`p` 行为每次探测延迟（**微秒整数**，如 `1200` = 1.2ms）；解析出主机名时还会输出 `d <索引> <主机名>` 行。

```bash
mtr -p 8.8.8.8
```

```
1 192.168.1.1 0 5 5 1 1 2
2 10.0.0.1 0 5 5 4 5 6
```

每行字段为 `跳号 主机 丢包 已收 已发 Best Avg Wrst`（毫秒取整；**无时间戳、无 Last/StDev**）。增量输出：只有某跳数据变化时才重打该行（供 mtr-gtk 等前端消费），跳数减少时输出 `-N` 删除多余行。

### 六、交互模式：TUI 控制（-t / --displaymode）

| 参数 | 说明 |
|---|---|
| `-t` | 显式使用 curses 界面（新版默认即此） |
| `--displaymode MODE` | 启动时的初始视图 |

```bash
mtr -t 8.8.8.8
mtr --displaymode 2 8.8.8.8   # 0=统计(默认) 1=无延迟条纹图 2=带延迟条纹图
```

交互界面快捷键：`p` 暂停（再按`空格`恢复）、`d` 切换显示模式、`r` 重置统计、`q` 退出。

### 七、名称解析与字段显示：看什么（-n / -b / -e / -o / -y / -z）

| 参数 | 说明 |
|---|---|
| `-n` | 不解析主机名，只显示 IP（快且不受 DNS 干扰） |
| `-b` | 主机名 + IP 同时显示 |
| `-e` | 显示 ICMP 扩展（MPLS 标签等） |
| `-o FIELDS` | 自定义输出字段 |
| `-y 0/1/2/3/4` | IP 归属信息：0=AS 号、1=IP 前缀（网段）、2=国家代码、3=RIR、4=分配日期 |
| `-z` | 显示 AS 号（等价 `-y 0`） |

```bash
mtr -r -n -c 5 8.8.8.8    # 只看 IP
mtr -r -b -c 5 8.8.8.8    # 都看
mtr -r -z -c 5 8.8.8.8    # 看 AS 号
mtr -r -y 1 -c 5 8.8.8.8  # 看 IP 前缀（网段）
mtr -r -e -c 5 114.114.114.114  # 看 MPLS
mtr -r -o "LS NABWV" -c 5 8.8.8.8  # 自定义列
```

```bash
mtr -r -z -c 5 8.8.8.8
```

`-o` 字段字母：`L`丢包率 `S`已发送 `R`已接收 `D`已丢弃 `N`最新 `A`平均 `B`最小 `W`最大 `V`标准差（完整列表见 `man mtr`）。
